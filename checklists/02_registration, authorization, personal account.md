## Общая информация

- Личный кабинет доступен **только авторизованным пользователям**.
- Вход в кабинет осуществляется с помощью **логина (email)** и **пароля**.
- После авторизации пользователь видит свои персональные данные, выбранную компанию и договор.
- Все разделы ЛК (кроме явно указанных) доступны только после авторизации.

## Регистрация нового пользователя

### Доступ к регистрации
- [ ] 👁 Кнопка **«создать кабинет»** присутствует:
  - В сайдбаре 
  - На отдельной странице авторизации
  - На странице неавторизованного пользователя
  - На Главной странице (для неавторизованного пользователя)
- [ ] 🔄 Нажатие кнопки «создать кабинет» открывает форму регистрации.

### UI/UX формы регистрации
- [ ] 👁 Форма содержит поля: **Email** и **Пароль**.
- [ ] 👁 Поле «Пароль» скрыто (отображается в виде точек/звёздочек).
- [ ] 👁 Присутствует кнопка **«получить код в письме»**.
- [ ] 👁 Все элементы формы отображаются корректно на всех разрешениях экрана.

### Валидация полей ввода
- [ ] ❌ При отправке пустых полей появляется сообщение о необходимости заполнения.
- [ ] ❌ При вводе некорректного email (без @, без домена и т.д.) появляется сообщение об ошибке.
- [ ] 🔄 При попытке использовать уже зарегистрированный email:
  - Код подтверждения не отправляется повторно
  - Необходимо самостоятельно воспользоваться функцией "Восстановление пароля"

### Подтверждение email
- [ ] ✅ После заполнения полей и нажатия кнопки **«получить код в письме»** на указанную почту приходит письмо с четырёхзначным кодом.
- [ ] ✅ Поле для ввода кода подтверждения отображается корректно.
- [ ] ✅ При вводе корректного кода открывается страница заполнения контактных данных (страница "Добро пожаловать").
- [ ] ❌ При вводе некорректного кода появляется сообщение об ошибке.
- [ ] 🔄 Кнопка повторной отправки кода становится доступной спустя 60 секунд после первичной отправки.

### Заполнение контактных данных
- [ ] ✅ После успешного подтверждения кода открывается форма с полями для контактных данных (ФИО, телефон и т.д.).
- [ ] 👁 Все обязательные поля имеют маркировку (звёздочка или надпись "обязательно").
- [ ] ❌ Форма не принимает пустые значения в обязательных полях (появляется сообщение об ошибке).
- [ ] ✅ После заполнения и нажатия **«сохранить и продолжить»** данные сохраняются.
- [ ] 🔄 Если на этапе регистрации была нажата кнопка добавления компании, после сохранения данных открывается форма создания компании.
- [ ] ✅ Если компания не добавлена, пользователь может вернуться к этому шагу позже из ЛК.

### Успешная регистрация
- [ ] ✅ После завершения всех шагов пользователь становится авторизованным и попадает в ЛК.
- [ ] 👁 В сайдбаре отображается имя пользователя.
- [ ] 👁 В разделе «Личные данные» отображается корректная информация о пользователе.
- [ ] 👁 Если компания добавлена — она отображается в сайдбаре и в разделе «Компании».
- [ ] 👁 Если компания не добавлена — отображается кнопка/предложение добавить компанию.
- [ ] ✅ Пользователю доступен расширенный функционал (все разделы ЛК в зависимости от статуса компании).

## Авторизация пользователя

### Доступ к авторизации
- [ ] 👁 Кнопка **«войти»** присутствует:
  - В правом верхнем углу сайдбара на всех страницах
  - На странице неавторизованного пользователя
  - На Главной странице
  - В Корзине (для неавторизованного пользователя)
- [ ] 🔄 При нажатии на кнопку открывается форма входа (сайдбар или отдельная страница).

### UI/UX формы входа
- [ ] 👁 Форма содержит поля: **Email** и **Пароль**.
- [ ] 👁 Присутствует кнопка **«войти»**.
- [ ] 👁 Присутствует ссылка **«Забыли пароль?»** для восстановления доступа.
- [ ] 👁 Все элементы формы отображаются корректно на всех разрешениях экрана.

### Позитивный сценарий входа
- [ ] ✅ Ввод корректного email и пароля → успешный вход в ЛК.
- [ ] ✅ После входа пользователь видит свои персональные данные в сайдбаре.
- [ ] ✅ В сайдбаре отображается выбранная компания и договор (если есть).
- [ ] ✅ Все разделы ЛК становятся доступны (с учётом прав и статуса компании).

### Негативные сценарии входа
- [ ] ❌ Ввод неверного пароля → сообщение об ошибке (например, *«Проверьте правильность написания логина или пароля»*).
- [ ] ❌ Ввод незарегистрированного email → сообщение об ошибке (например, *«Проверьте правильность написания логина или пароля»*).
- [ ] ❌ Попытка входа с пустыми полями → сообщение о необходимости заполнения (например, *«Обязательное поле»*).

### Восстановление пароля
- [ ] 🔄 При нажатии на ссылку «Забыли пароль?» открывается форма восстановления.
- [ ] ✅ При вводе зарегистрированного email на почту приходит письмо с инструкцией по сбросу пароля.
- [ ] ✅ После сброса пароля можно войти в ЛК с новым паролем.
- [ ] ❌ При попытке восстановить пароль для незарегистрированного email появляется сообщение об ошибке (например, *«Пользователь с логином ${name} не найден»*).

## Выход из личного кабинета

- [ ] 👁 Кнопка/иконка «выйти» отображается:
  - В правом верхнем углу сайдбара
  - В блоке "Личный кабинет" на Главной странице
- [ ] ✅ При нажатии на кнопку происходит выход из аккаунта.
- [ ] 🔄 После выхода:
  - Если пользователь был на странице ЛК → перенаправляется на страницу неавторизованного пользователя
  - Если пользователь был на общей странице → остаётся на ней, но теряет доступ к функциям ЛК
- [ ] ✅ После выхода доступ к ЛК и всем его разделам блокируется.
- [ ] 🔄 При попытке перейти по прямой ссылке на раздел ЛК:
  - Открывается страница неавторизованного пользователя
  - ИЛИ отображается сообщение об отсутствии доступа

## Структура и разделы личного кабинета

### 6.1. Главная кабинета (Дашборд)

#### UI/UX
- [ ] 👁 На странице отображаются следующие блоки:
  - Обращения
  - Заказы
  - Помощь
  - Товары (Покупки, Избранное, Просмотренные)
  - ТОП-10 покупок
  - Черновики
  - Компании
  - Сводка по суммам (по компаниям/по категориям/за период)
- [ ] 👁 В сайдбаре отображается текущая выбранная компания и договор.
- [ ] 👁 Хлебные крошки отображаются и корректно работают (т.е. кликабельны).
- [ ] 👁 Блок "Помощь" при необходимости разворачивается или сворачивается.

#### Функциональность
- [ ] ✅ При клике на интерактивные элементы (блоки, ссылки) происходит переход в соответствующий раздел.
- [ ] 🔄 Счётчики в блоках (количество заказов, обращений и т.д.) отображают корректные значения.
- [ ] ✅ Все числовые данные (цены, скидки, суммы в диаграммах) достоверны и рассчитаны верно.
- [ ] ✅ Во всех разделах с товарами работает сортировка.
- [ ] ✅ Взаимодействие с черновиками на дашборде синхронизировано с разделом «Черновики»:
  - При удалении черновик удаляется в обоих разделах
  - При добавлении в корзину черновик перемещается в корзину в обоих разделах
- [ ] 🔄 При отсутствии данных в каком-либо из блоков отображается информативная заглушка.
- [ ] 🔄 Ссылки на подробную инструкцию в разделе «Помощь» ведут на актуальные страницы.
- [ ] 🔄 Баббл с менеджером отрабатывает корректно (анимация, открытие чата).

- [ ] ✅ Счётчик товаров показывает верное значение.
- [ ] ✅ Доступна опция "Поделиться заказом" (генерируется корректная ссылка).
- [ ] ✅ **«Опционально»:** Доступен счёт на оплату (для соответствующих статусов).
- [ ] 🔄 При клике на конкретный заказ открывается страница с подробной информацией.

### 6.4. Компании

#### UI/UX
- [ ] 👁 В разделе кликабельные хлебные крошки.
- [ ] 👁 Отображается список всех компаний, привязанных к аккаунту.
- [ ] 👁 Данные компании (название, ИНН, статус) отображаются корректно.

#### Функциональность
- [ ] ✅ Пользователь может добавлять новые компании.
- [ ] ✅ Пользователь (с правами администратора) может управлять сотрудниками компаний:
  - Менять статус (активен/заблокирован)
  - Менять роль (сотрудник/администратор)
- [ ] 🔄 Добавление сотрудников происходит несколькими способами:
  - По приглашению (администратор отправляет приглашение)
  - По заявке (пользователь подаёт заявку на вступление)
- [ ] 🔄 **«Опционально»:** Есть возможность покинуть компанию по кнопке (если пользователь — не единственный администратор).
- [ ] 🔄 В списке компаний отображается статус каждой компании. Функционал меняется в зависимости от статуса.
- [ ] 🔄 Можно переключаться между компаниями для смены контекста работы (меняются данные на дашборде, цены на товары).
- [ ] 🔄 Можно менять соглашения. От них зависят цены на товары и условия оформления заказа.
- [ ] 🔄 Ссылка на подробную инструкцию в разделе «Помощь» работает корректно.

### 6.5. Черновики

#### UI/UX
- [ ] 👁 Раздел доступен только пользователям с **активной (подтверждённой) компанией**.
- [ ] 👁 В разделе кликабельные хлебные крошки.
- [ ] 👁 На общей странице черновиков отображаются:
  - Название черновика
  - Содержание (список товаров)
  - Дата и время создания
  - Предварительная сумма
- [ ] 👁 На странице конкретного черновика дополнительно отображаются:
  - Возможность редактировать название
  - Фильтр по наличию товаров
  - Каждая позиция в составе отдельно

#### Функциональность
- [ ] ✅ Пользователь может редактировать черновик: изменять состав заказа.
- [ ] ✅ Пользователь может выгрузить черновик в корзину для дальнейшего оформления.
- [ ] ✅ Пользователь может удалить черновик.
- [ ] ✅ Пользователь может поделиться черновиком (если функция доступна).
- [ ] ❌ Если у пользователя нет активной компании, раздел недоступен (отображается заглушка или переадресация).

## Частые ошибки

### Бэкенд
- [ ] ❌ **502 Bad Gateway** — при попытке входа/регистрации во время технических работ на бэке.
- [ ] ❌ **500 Internal Server Error** — при создании нового пользователя, если не все данные переданы корректно.
- [ ] ❌ Ошибки при отправке кода подтверждения (письмо не приходит, приходит с задержкой).

### Фронтенд (визуальные и логические баги)
- [ ] 👁 Кнопка «войти» отображается на всех страницах сайта (включая 404 и другие служебные страницы).
- [ ] 👁 Модальные окна корректно отображаются на мобильных устройствах (все поля видны, есть прокрутка).
- [ ] 👁 Текст ошибок при вводе данных читаемый, соответствует дизайн-гайдам.
- [ ] 👁 Данные пользователя после входа отображаются во всех разделах корректно.
- [ ] 👁 Сайдбар со списком разделов отображается корректно на всех разрешениях.
- [ ] 🔄 При переключении между разделами ЛК контекст текущей компании не теряется.
- [ ] 🔄 При переходе в другой аккаунт данные предыдущего пользователя недоступны (кеш очищается).
